# Threads 글쓰기 워크플로우: 초안 작성부터 발간까지

## 목표
사용자가 제공한 아이디어나 문서를 바탕으로 **Threads 발행용 콘텐츠를 작성**하고, 사용자 확인 후 **Threads 발행 경로에 최종 저장**합니다.

## 핵심 원칙
1. **사용자 입력 수집** → 아이디어, 초안, 또는 문서 제공받기
2. **AskUserQuestion으로 확인** → 타겟 오디언스, 목적, 톤 등 확인
3. **초안 작성 및 채팅 컨펌** → 완성된 콘텐츠를 사용자에게 제시하고 승인 받기
4. **최종 저장** → Threads 발행 경로(`3.쓰레드_포스팅/10_Published/`)에 저장

## 실행 단계

### 0단계: 사용자 입력 수집 및 AskUserQuestion 제시

사용자가 다음 중 하나를 제공합니다:
- **아이디어**: "~하는 내용의 글을 쓰고 싶어"
- **초안**: 이미 작성된 글의 초안 제공
- **문서**: 수정/개선할 기존 문서 제공

**사용자 입력 후, AskUserQuestion으로 맥락 확인 (4개 질문):**

#### 질문 1: 콘텐츠 소스
- 헤더: "입력 형식"
- 옵션:
  - `아이디어`: "내용 주제만 제공했어요"
  - `초안`: "이미 초안을 작성했어요"
  - `기존 문서`: "기존 문서를 개선하고 싶어요"
  - `Other`: 기타

#### 질문 2: 타겟 오디언스
- 헤더: "타겟"
- 옵션:
  - `취준생`: 취업 준비 중인 사람들
  - `신입사원`: 회사 새로 입사한 사람들
  - `비개발자`: 기술 지식 없는 일반인
  - `Other`: 기타

#### 질문 3: 콘텐츠의 목적
- 헤더: "목적"
- 옵션:
  - `정보 & 팁`: "이것을 알아야 해" - 실용적 정보 전달
  - `경험 & 공감`: "내 경험을 나눌게" - 개인 경험 공유
  - `문제 해결`: "이렇게 해결했어" - 실제 해결책 제시
  - `Other`: 기타

#### 질문 4: 글의 톤과 스타일
- 헤더: "톤"
- 옵션:
  - `단문 스타일`: 짧고 임팩트 있는 정보 전달
  - `장문 스타일`: 자연스러운 흐름의 스토리 중심
  - `혼합 스타일`: 정보와 경험의 균형
  - `Other`: 기타

---

### 1단계: 초안 작성 (사용자 응답 기반)

사용자의 입력 형식에 따라 처리:

**A. 아이디어 입력 시:**
1. 사용자가 제시한 주제/아이디어를 바탕으로 새로운 Threads 콘텐츠 작성
2. 선택된 타겟, 목적, 톤에 맞게 작성
3. Threads 특성에 최적화 (길이, 가독성, 임팩트)

**B. 초안 입력 시:**
1. 사용자 초안 분석
2. 타겟과 목적에 맞게 내용 재구성
3. 선택된 톤으로 문체 개선

**C. 기존 문서 입력 시:**
1. 문서 분석
2. Threads 발행용으로 압축/개선
3. 타겟 오디언스 눈높이에 맞게 수정

**자동 교정 기준:**
- 정중한 표현 → 자연스러운 대화체로 변경
- 어색한 접속사 정리
- 반복 표현 제거
- 문장 길이 최적화
- 전문용어 → 쉬운 단어로 치환
- 수동적 표현 → 능동적 표현으로 변경

### 1단계: AskUserQuestion으로 맥락 확인

사용자의 응답을 통해 다음 정보를 수집합니다:
- `입력 형식`: 아이디어 / 초안 / 기존 문서
- `타겟 오디언스`: 취준생 / 신입사원 / 비개발자 / 기타
- `콘텐츠 목적`: 정보 & 팁 / 경험 & 공감 / 문제 해결 / 기타
- `글의 톤`: 단문 / 장문 / 혼합 / 기타

### 2단계: Threads 콘텐츠 작성

사용자 응답을 바탕으로 초안 작성:

**입력 형식별 처리:**

**A. 아이디어 입력 시:**
- 주제/아이디어를 바탕으로 새로운 콘텐츠 작성
- 타겟 오디언스와 목적에 맞게 구성
- 선택된 톤으로 작성

**B. 초안 입력 시:**
- 기존 초안 분석
- 내용 재구성 및 문체 개선
- 타겟과 목적에 맞게 조정

**C. 기존 문서 입력 시:**
- 문서 분석 및 Threads 발행용 압축
- 타겟 오디언스 눈높이에 맞게 수정

**자동 교정 항목:**
- 정중한 표현 → 자연스러운 대화체
- 어색한 접속사 정리
- 반복 표현 제거
- 문장 길이 최적화
- 전문용어 → 쉬운 단어
- 수동적 → 능동적 표현

**예시:**
```
원문: "이 방법은 매우 효율적이므로 생산성을 향상시킵니다."
개선: "이 방법 진짜 효과 있어. 생산성이 확 올라간다."
```

### 3단계: 초안 채팅 컨펌

완성된 Threads 콘텐츠를 제시:

```
## Threads 콘텐츠 초안

**타겟 오디언스**: [사용자 선택]
**콘텐츠 목적**: [사용자 선택]
**글의 톤**: [사용자 선택]

---

[완성된 콘텐츠]

---

**적용된 개선사항:**
- 자연스러운 대화체로 변환
- [오디언스 특성에 맞는 표현 조정]
- [톤에 맞는 문장 구조 조정]
```

**사용자 선택:**
- ✅ **승인**: 최종 저장으로 진행
- 🔧 **수정**: 구체적인 수정 요청
- ❌ **다시 작성**: 다른 방향으로 재작성

### 4단계: 최종 파일 저장

확정된 콘텐츠를 Threads 발행 경로에 저장:

**저장 위치**: `3.쓰레드_포스팅/10_Published/`

**파일명 형식**: `[날짜]_{제목}.md`

**메타데이터 추가**:
```markdown
---
title: [제목]
target_audience: [취준생/신입/비개발자]
purpose: [정보/경험/문제해결]
tone: [단문/장문/혼합]
created_date: [작성일]
status: ready_to_publish
---
```

**저장 완료 후 안내:**
- 파일 경로 확인
- Threads 발행 완료 안내
- 필요시 추가 편집 옵션 제시

## 워크플로우 요약

```
사용자 입력 (아이디어/초안/문서)
    ↓
AskUserQuestion (타겟, 목적, 톤 확인)
    ↓
Threads 초안 작성
    ↓
초안 채팅 컨펌 (사용자 승인)
    ↓
최종 저장 (3.쓰레드_포스팅/10_Published/)
    ↓
발행 완료
```

## 실행 예시

### 아이디어 기반 작성 흐름
```
사용자: "AI 시대에 신입 개발자가 갖춰야 할 마음가짐에 대해 쓰고 싶어"

↓ AskUserQuestion
- 입력 형식: 아이디어
- 타겟: 신입사원
- 목적: 경험 & 공감
- 톤: 혼합 스타일

↓ 초안 작성 (톤과 타겟에 맞게)

↓ 사용자 피드백: "좋아, 저장해줘"

↓ 최종 저장
→ 3.쓰레드_포스팅/10_Published/[2025-11-05]_AI시대 신입개발자 마음가짐.md
```

### 저장된 파일 구조
```markdown
---
title: AI 시대 신입 개발자의 마음가짐
target_audience: 신입사원
purpose: 경험 & 공감
tone: 혼합
created_date: 2025-11-05
status: ready_to_publish
---

[Threads 발행용 콘텐츠]
```

## 핵심 원칙

### DO ✅
- **사용자 입력 우선**: 아이디어/초안/문서 모두 수용
- **명확한 맥락 확인**: AskUserQuestion으로 타겟, 목적, 톤 파악
- **자연스러운 대화체**: 읽기 편하고 공감 가능한 표현
- **타겟 맞춤화**: 취준생/신입/비개발자 특성에 맞게 작성
- **빠른 저장**: 최종 승인 후 자동으로 3.쓰레드_포스팅/10_Published/ 경로에 저장

### DON'T ❌
- 정중하거나 어색한 표현 사용
- 사용자 확인 없이 저장하기
- 복잡한 문법 구조
- 반복되는 표현
- 잘못된 경로에 저장

## 톤 가이드

**단문 스타일 (정보 전달):**
- 짧고 임팩트 있는 문장
- 한 문장 = 한 아이디어
- "이것 알아야 해." 느낌

**장문 스타일 (경험/공감):**
- 자연스러운 흐름
- 따뜻한 톤
- "내 경험을 나눌게" 느낌

**혼합 스타일:**
- 정보와 경험의 균형
- 실용성 + 감정 소통
